# Adversarial review — 2026-08-18

Ran a seven-person panel (5 built-in + 2 generated) in parallel with `dev-deep-review`, while the
coordinator did execution verification alongside. Found **9 Blockers and 14 Majors**.

One thing about the panel composition first — the persona in the repository,
`.claude/deep-review-agents/ir-evaluation-expert.md`, is `RUN_START_LOCAL` (untrusted) under the
skill's trust boundary, so it was **not used**; a fresh persona with the same lens replaced it.
A persona body goes verbatim into the subagent prompt, so it can end up executing instructions
the repository planted.

## Blockers

### B1 · masking verification blocked nothing

`ingest_sessions.py` would `print` when it found a residual secret and **exit 0**.
Worse, `session_docs.json` was written **before** that check.

```
   before   ① write the file  →  ② check  →  ③ print ❌  →  ④ exit normally
                                                ↑ already on disk and flowed downstream
   now      ① check  →  on failure sys.exit(1), writing nothing  →  ② write the file (chmod 600)
```

The only control was "a log line a human might read".

### B2 · the patterns missed 24 of 30 synthetic samples

In particular, **Claude Code's own credential format** (`sk-ant-oat01-`) was absent — the existing
pattern required a literal `api\d{2}`, and `~/.claude/.credentials.json` gets `cat`-ed in sessions
often.

Expanded from 12 kinds to **27**. Confirmed detection of all 20 synthetic samples.
Newly covered: Claude OAuth/sid/admin · OpenAI svcacct · GitHub fine-grained PAT ·
Slack xapp/xoxe/xoxd · AWS STS · Google API · Stripe · GitLab · npm · HuggingFace · Telegram ·
Discord webhook · **DB connection strings** · context-based generic secrets.

DB connection strings were not hypothetical — `postgresql://user:pw@host` was alive inside a
`session_docs.json` that claimed masking was complete.

### B3 · the tool that removed secrets preserved them forever

`remask_docs.py` copied the original to `.bak` and then masked. Which means **the unmasked copy
stayed.** Measured: an unmasked PRIVATE KEY sat inside `session_docs.json.bak` — while the very
reason that tool existed was that pattern gap.

`.bak` creation was removed in favour of a temp file plus an atomic `os.replace`.
The two existing `.bak` files on disk were masked in place and tightened to 600.

### B4 · there was no DB write lock

`schema_v3`, `sync_v3`, and `manual_index` all use `mode="overwrite"` with no lock. Overlap does
not crash — it leaves a **silently inconsistent DB**. Added
[`kal_lock.py`](../src/kal_lock.py) — it does not wait; it **says who holds it and dies
immediately** (writes take 90 seconds to 3 hours, and waiting silently looks like a hang).

### B5–B7 · the docs contradicted each other

```
   weights     kal_search.py docstring  .15/.20/.15/.50
               PRESETS (60 lines below) .18/.05/.18/.59   ← the real one
               PIPELINE.md:322          .15/.20/.15/.50
   viewer      README·PIPELINE "export_webgl.py (recommended)"
               rebuild_all.sh "deprecated · calling it overwrites the artifacts"
   merging     README "proposed, not applied"  vs  ENTITY_RESOLVE.md "applied"
```

All three were wrong **in the direction that misleads the reader**.

### B8–B9 · the sharing risk was unwarned, and a prior review vouched for its safety

`viewer/galaxy.html` is self-contained, making it **the only artifact designed to leave the
machine** — and it contains 374 document paths verbatim (the filename *is* the topic), 137
persons, 234 organizations, and internal hostnames. Masking only looks at credentials, so all of
it passes.

Worse, [`REVIEW-2026-08-17.md`](./REVIEW-2026-08-17.md) recorded this file as **"0"** — with no
qualifier that it meant credentials only. That line was corrected, and `esbuild.web.mjs` now
states the contents on every build.

### Why M4 is a Major

`table_names(limit=10)` does not paginate automatically. There are 8 today; `sync_v3` creating
`stale_docs` makes 9. **The moment there are 11, the verifier silently omits one** — the verifier
going blind is the worst kind of defect.

### M12, demonstrated

```
   ① in cluster mode, hide "하이브리드 검색 시스템"   7,756 → 7,051
   ② switch to type mode                          filters [] · 7,756   ← no leak
   ③ in type mode, hide concept                    4,412
   ④ back to cluster mode                          restored · 7,051
   ⑤ back to type mode                             restored · 4,412
```

Previously, at ② the cluster name was compared against folder/type names, so it was either a
ghost filter hiding nothing or a coincidental name match hiding something silently.

## Two defects in the checker itself

While fixing `verify_docs.py` during the review, the same trap was hit **twice**.

1. Guessing values by context regex flagged `"500-char chunk"` (the storage chunker) as a
   `CHUNK_CHARS` (extraction, 2400) violation, and the example flag `--top 30` as an `ANSWER_N`
   (20) violation.
2. Treating the prose `"N entities"` as a DB total flagged the extraction cache (8,406), cluster
   coverage (6,386), and pre-merge history (8,121) all as false positives.

**A checker that cries wolf is worth zero.** Both were inverted to **opt-in** — the line you want
verified names the constant, or carries the `<!-- db-count -->` marker.

There was also a bug where the checker died with a `ValueError` the instant it found something
(the constant is a string but `{got:>9,}` formats with `,`). The exception went to stderr, so it
**looked like "✅ everything matches".** A checker dying silently is worse than no checker.
